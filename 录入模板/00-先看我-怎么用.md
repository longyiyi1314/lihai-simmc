## 改的时候四条规矩

1. **`职位ID` / `职务ID` / `疆域ID` / `牵头机构ID` 是外键**，必须能在对应表里找到，否则构建会直接报错（这是故意设计的，防止写错字导致页面悄悄缺人）。
2. **一格里有多个值，用竖线 `|` 隔开**，不要用逗号——逗号是 CSV 的分列符。
3. **`id` 列是网址的一部分**（`/members/<id>/`），只能小写英文 + 数字 + 短横线；**填好就不要再改**，改了旧链接会 404。中文名写在「展示名」。
4. **保存为「CSV UTF-8（逗号分隔）」**。用 Excel 直接另存即可；如果弹出编码提示，选 UTF-8。

## 「任职」列怎么填

成员的机构/地名任职**统一写在这一列**，不再分别记在机构表、地名表里。格式：

```
org:机构ID:head|place:地名ID:member|place:地区ID:deputy
```

- `org:` 指机构（`04-职务分工` 的牵头机构、`data/organizations.json` 里的任意机构）；`place:` 指地名（`05-疆域` 或 `data/places.json` 里的任意地名）。
- 末尾的 `head` / `deputy` / `member` 分别是负责人 / 副职 / 普通成员。
- 一格多个任职用 `|` 隔开。改这里，页面上机构树、地名树里的人会自动跟着变。

## 三件只有你能做的事

1. **简介**：31 人里目前只有 2 位有简介（祁钰师、Heinrich4084），其余站点上显示「简介尚未录入」。**我不编造**——你给我文字，我就填进去；每人 60–120 字最好看。
2. **任职**：谁在哪任职、是不是负责人，都写在「任职」列。给全了，机构树和地名树就完整了。
3. **加入时间 / 头像 / 社交账号**：这几项新模型已不再单独记录（旧数据里也全是空的）。如需恢复，请告诉我，我再加回字段。
